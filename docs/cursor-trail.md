# Глобальный декоративный след курсора

`src/effects/CursorTrail/CursorTrail.tsx` добавляет один прозрачный Canvas
один раз на уровне App, после содержимого страницы. Фиксированный слой
покрывает viewport, включая все текущие и будущие секции. `z-index: 3` размещает
след над main (`z-index: 1`), а GlobalAtmosphere остаётся позади (`z-index: 0`).
`pointer-events: none` пропускает клики к бобам и другим элементам; стандартный
курсор, тексты, изображения и их слои не изменены. Scroll Snap не затронут.
Canvas не использует ассеты или URL,
поэтому base `/karina/` не требует специальных путей.

## Настройки

Блок `cursorTrail` в `src/effects/config.ts`:

- `enabled`: независимое отключение эффекта.
- `maxParticles: 35`: жёсткое ограничение числа частиц.
- `spawnSpacing: 12`: минимальное расстояние движения до следующего выпуска.
  Увеличение делает след реже.
- `spawnIntervalMs: 32`, `maxSpawnPerMove: 3`: ограничение частоты и размера
  пакета. При быстром движении пакет распределяется равномерно вдоль отрезка,
  а не концентрируется в его конце. Пропущенные события не образуют очередь.
- `minLifetimeMs: 400`, `maxLifetimeMs: 800`: время до полного исчезновения.
- `minSize: 2`, `maxSize: 7`: размеры в CSS px; редкая искра крупнее в 1.35 раза.
- `spread: 15`: максимальное смещение от места рождения по каждой оси.
- `opacity: 0.8`: яркость; `glowBlur: 6`: мягкое свечение.
- `colors`: розовый #FF84B9, жёлтый #FFDF50, голубой #8CCEFF,
  фиолетовый #B598FF и оранжевый #FFAE70.
- `maxDpr: 2`: предел разрешения backing buffer для экономии памяти.

Большинство частиц — точки, часть — четырёхконечные звёздочки, около 6% —
чуть более крупные искры с белой сердцевиной. Поворот, дрейф, уменьшение
и прозрачность вычисляются относительно времени рождения, без React setState.
Размеры учитывают devicePixelRatio, resize viewport и смену разрешения экрана.

## Жизненный цикл и доступность

Источник — один пассивный pointermove на document, только для pointerType mouse.
Координаты clientX/clientY непосредственно соответствуют фиксированному Canvas.
В Hero больше нет экземпляра эффекта или подписок CursorTrail. Общего источника
pointer-событий в проекте нет: существующий GlobalAtmosphere не изменяется,
каждый эффект сохраняет свой независимый лёгкий обработчик.
На устройствах без hover/fine pointer и при reduced motion Canvas отключён.
CSS дополнительно скрывает его, а каждый RAF и событие проверяют media queries.
При изменении предпочтений, скрытии вкладки или размонтировании отменяются
RAF и активные частицы. Обработчики, ResizeObserver и media listeners очищаются.

После остановки мыши новые частицы не создаются: RAF работает только до
истечения последней частицы. При выходе из окна старые частицы естественно
затухают; запоминание траектории сбрасывается. Прокрутка не создаёт частиц,
не сбрасывает след и не меняет его систему координат: Canvas остаётся закреплён
во viewport. Повторные pointermove с теми же координатами игнорируются.
Canvas ограничивает рисунок своими размерами и не создаёт переполнения.

## Проверка

TypeScript и `npm run build` проходят. В Chrome через production preview
`/karina/` проверены медленное/быстрое движение, равномерный выпуск по отрезку,
неподвижный курсор и естественное исчезновение. По Canvas-вызовам измерен
пик ровно 35 частиц и отсутствие кадров после завершения последней частицы.
Проверены все семь секций (Hero и Intro/Gallery трёх проектов), привязка частиц
к client-координатам после прокрутки, сохранение единственного Canvas при
переходах, выход из окна, реальные клики сквозь Canvas, совместная работа
с Bean Party, GlobalAtmosphere и Scroll Snap вниз/вверх.

Проверены 1920×1080 при DPR 2, 1440×900 при DPR 1.5, 1024×768 и touch-эмуляция
768×1024, 390×844: на touch Canvas отсутствует, переполнения нет.
Дополнительно проверены смена DPR/ширины, reduced motion, остановка курсора
при прокрутке и обычная якорная ссылка сквозь Canvas. Ошибок JavaScript
и гидратации не обнаружено; прежний сетевой запрос favicon.ico с 404
не относится к этому эффекту.
